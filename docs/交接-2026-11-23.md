- **上傳到 server.pro、重開伺服器前要使用者明確說「上傳並重開」**（或類似的話）才做；做之前確認沒人在線上。
- 不要自己改現有的平衡數值；新功能的預設值可以先訂，寫進 config 讓他調。
- 本機 test-server 跑在 app 的 Terminal 分頁時，不要送 Ctrl+C（會直接結束沒存檔）；用 `restart.flag` 或請使用者打 `stop`。

- 電腦有 Windows 核心記憶體洩漏（paged pool 會漲到 70 GB 以上）：暫存伺服器開不起來時先看記憶體，`./gradlew --stop` 能省一點；建議使用者重開電腦。

## 下一個任務：場景模型改成「方塊外觀」

> **2026-11-23 深夜做了（等使用者進遊戲看）**：沒有照下面直接把方塊放進世界，改成「世界裡照舊放屏障，同一格用 block display 顯示換過外觀的方塊狀態」。原因：
> - 彩釉陶瓦這類實心方塊會把旁邊方塊的面剔除（從模型旁邊看得到地板、牆裡面），格子裡面的光是 0（模型非發光的部分會變黑），而且是 solid 渲染層，60 張貼圖的透明像素會變成實色。
> - 不實心、有 facing 的原版方塊沒有夠多「不會自己變」的狀態，碰撞也不對。
> - block display 是實體：不碰撞、不剔除、光照照實體位置，用的方塊狀態不會出現在世界上，所以可以借紅石線（1296 個狀態、cutout 渲染層、地圖沒用）。
> 實作：`tools/make_scene_blocks.py`、`game/SceneBlocks.java`、`Models.spawnBlock`；`models.scene-mode: item` 換回舊做法，`models.scene: false` 用回原本的方塊。下面是原本的計畫，留著參考。

使用者同意試，**不行就用回原本的方塊**（`models.scene: false` 就是原本的方塊）。

### 為什麼要換

現在 `game/SceneModels.java` 在功能方塊上疊 item display，位置、朝向靠程式推算（`frontYaw`、`Models.flip`），模型包裡每個模型在格子裡的位置不一樣（例如配電箱、貨梯配電盤是貼著格子一邊的牆面板），結果常常沒貼牆、浮在旁邊。使用者截了好幾張。

### 做法

用資源包把「地圖上沒用到的原版方塊」的外觀換成我們的模型（`assets/minecraft/blockstates/<方塊>.json` 指到 `ghosthunt:item/classic/<模型>`），地圖上放這些方塊：
- 模型會長在方塊格子裡，一定對齊。
- 朝向用方塊的 `facing` 狀態；個別模型方向反了，在 blockstates json 裡改 `y` 就好。
- 狀態變化（讀卡機紅燈／倒數／綠燈、木桶上鎖／翻過、配電箱壞／修好）用換方塊或換方塊狀態做。

### 步驟建議

1. 找沒用到、有水平 `facing` 的方塊：彩釉陶瓦（16 色）最適合。先 grep 確認沒在地圖用到：`src/main/resources/pve-maps/*.txt`、`docs/pve-maps/blueprints/*.md`、`building/*.java`、`Lobby.java`。
2. 狀態數：木桶 3、終端機 2、讀卡機 4、無線電 2、監控螢幕 2、配電箱 2、貨梯配電盤 3、販賣機 2、紙條講台 2、廣播台 1、攝影機 1，**共 24 種，超過 16 色**。
   - 可以再找其他沒用到的 facing 方塊（例如 `beehive`／`bee_nest` 有 facing×honey_level 0～5）。
   - 或減少狀態數。
3. 先確認模型貼圖有沒有半透明：彩釉陶瓦是 solid 渲染層，半透明會變黑。有的話就換用 cutout 層的方塊。`*_glow.png` 也要看。
4. 模型高度：2 格高的（配電箱、販賣機、監控螢幕、電源）下面那格是模型方塊，上面那格放屏障（擋路）。AI 視線照 `Match.rayHits` 的規則把那格當實心。
5. 蓋地圖時決定方向：
   - `FixedMapGenerator` 放功能物件的地方（`sideObjects()` 的 F/R/N/M/A/Z、`securityTerminals`、木桶 `barrels()`、讀卡機）改放新方塊。
   - `facing` 朝走道，照 `SceneModels.frontYaw` 的找牆邏輯：背後是實心方塊、對面走得到。
   - `Objectives.isContainer` 現在看 BARREL／BARRIER，要改成也認新方塊。上鎖的木桶原本在上面放鐵活板門，換成「上鎖」狀態的方塊。
6. 狀態更新：把 `SceneModels.tick()` 改成換方塊狀態，不再生 item display。
7. 大廳 `Lobby.overlayModel` 也改成放方塊。
8. 模型包原檔在使用者的 `Downloads/ghosthunt_models.zip`（classic 資料夾）。我們只複製了 `resourcepack/assets/ghosthunt/{items,models/item,textures/item}/classic/`。`java_scales.json`：大門、監獄、櫃子、貨梯門的模型縮小過，要放大 1.4～1.75 倍，用方塊外觀做不到放大，這幾個先別做。
9. 測試：
   - 暫存伺服器 `scratchpad/srv`（舊 session 的，可能沒了；沒有就用 test-server）跑 `/gh build pve mall2`、`/gh selftest`、`/gh start ai normal auto solo`。
   - 外觀要使用者進遊戲看。
